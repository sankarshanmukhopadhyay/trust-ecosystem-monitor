# Contributing

For substantive changes, preserve an Issue → PR → tests/evidence → merge trail. State the observed problem or proposition, affected ecosystem/profile and authority boundary; implement the smallest coherent change; add regression/negative evidence for consequential behaviour; and merge only after applicable validation passes.

Discovery, admission, collection intensity and taxonomy are separate decisions. Do not infer monitoring authority from organization membership. For governed profiles, repository inclusion/watch decisions must carry rationale and evidence; unresolved cases should remain fail-closed rather than being widened for convenience.

Do not force ambiguous external repositories into a taxonomy merely to eliminate `Unclassified`. Missing or ambiguous evidence must remain explicit.

Source, profile, policy and workflow changes belong on PR-governed `main`. The `generated-observations` branch is automation-owned operational evidence and should not be used as a source-authoring branch.

Security reports must follow [`SECURITY.md`](SECURITY.md).
